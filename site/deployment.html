服务端部署检查

上线不是上传源码后运行一个命令。必须先完成许可证、依赖、配置、状态机、结算、安全、监控和合规检查。

干净环境构建

记录 Linux、GCC/G++、Tars、系统库和 Unity 版本；清理绝对路径；锁定依赖；在全新环境执行最小构建。没有 Unity Assets/ 时，不要声称客户端可完整构建。

配置与密钥

扫描完整 Git 历史中的密码、令牌、私钥、生产地址和个人数据。删除文件不能让历史凭据失效，疑似泄漏的凭据必须轮换。

游戏与结算完整性

服务端应权威控制牌、动作、时间、余额和结果。测试重放、重复消息、并发动作、断线重连、超时、重复结算、订单幂等、机器人与合谋风险，并保留可审计日志。

生产运维

补充健康检查、结构化日志、指标、告警、限流、最小权限、备份、恢复演练、回滚、事故响应和依赖漏洞管理。

发布说明

Release 必须列出实际包含的客户端、服务端、数据库和后台组件，以及构建状态、校验值、兼容性和已知限制。不要把产品截图当作完整性证明。
