# Contributing

Contributions that improve build reproducibility, protocol documentation, game-state correctness, tests, security, and accessibility are welcome.

## Before opening an issue

Search existing issues and document the exact commit, operating system, compiler, Tars version, command, expected result, actual result, and first relevant error. Remove passwords, tokens, private endpoints, personal data, and proprietary assets.

## Pull requests

1. Keep changes focused and explain the affected Match, Order, protocol, game-flow, Unity metadata, or documentation area.
2. Add tests for behavior changes where a runnable test harness exists.
3. Describe compatibility, configuration, database, and rollback impact.
4. Do not commit generated `.d` files, binaries, logs, caches, credentials, or production configuration.
5. Confirm that contributed code and media may legally be distributed under the repository's final licensing model.
6. Update documentation and `CHANGELOG.md` when behavior or public interfaces change.

The current license text requires maintainer review. Contributors should not assume that “commercial licensing” language overrides or narrows an open-source grant without a legally consistent license.
